# DPCM: A Dual-domain Prototype and Constraint-guided Model for Multivariate Time Series Anomaly Detection

PyTorch implementation of DPCM. The Dual-domain Prototype-Constrained Reconstruction module (DPR) learns temporal and spectral prototypes. The Temporal State Transition Constraint (TSTC) and Variable Collaborative Pattern Constraint (VCPC) score temporal prototype states. The default method combines reconstruction, temporal transition, and cross-variable scores after empirical cumulative distribution function (ECDF) calibration.

## Installation

Use Python 3.10 or later in a clean environment.

```bash
python -m pip install -r requirements.txt
```

For CUDA training, install the PyTorch build that matches your platform and CUDA driver. The application uses CUDA when available.

## Data preparation

Download the anomaly-detection data and metadata from [TAB](https://github.com/decisionintelligence/TAB). Put `DETECT_META.csv` in `data/tab/` and the original multivariate CSV files in `data/tab/multi_ts/`.

| Benchmark | CSV file | Configuration |
| --- | --- | --- |
| CalIt2 | `CalIt2.csv` | `config/calIt2/calIt2.yaml` |
| DLR | `249_DLR.csv` | `config/dlr/dlr.yaml` |
| MSL | `MSL.csv` | `config/msl/msl.yaml` |
| PSM | `PSM.csv` | `config/psm/psm.yaml` |
| SWAN | `SWAN.csv` | `config/swan/swan.yaml` |
| SWaT | `SWAT.csv` | `config/swat/swat.yaml` |

The loader uses the chronological split from the TAB metadata and fits standardization on the training partition. The MSL preset uses its first channel. PSM and SWaT default to downsampling by factors of 20 and 50, respectively. Training uses every starting offset as a separate sequence, and each training window stays within its offset. Calibration and testing use offset zero within their respective chronological partitions, with labels sampled at the same indices. Other datasets use the original sampling rate. Pass `--sample_stride 1` to use the original sampling rate for PSM or SWaT, including when evaluating a checkpoint trained on the original data.

## Train and evaluate

From the repository root, train and evaluate the default detector on CalIt2 as follows. Choose a new `--filename` for each distinct run configuration to keep checkpoints and reports separate.

```bash
python main.py --config config/calIt2/calIt2.yaml --mode "train test" --report_variant ecdf_tree --metrics "auc vus" --filename calit2_dpcm --seeds 0
```

To evaluate an existing checkpoint, rerun the command with `--mode test`, the same filename, and the same seed. Checkpoints are saved under `results/`. The default detector writes its four threshold-independent metrics to `report/calit2_dpcm_chowliu_ecdf_fusion.csv`. Use your own checkpoints generated by this repository.

Training uses 5,000 optimizer updates per seed by default. Set `max_steps` in YAML or pass `--max_steps` to override it. Use a different `--filename` to keep checkpoints for multiple budgets. Test-only runs can load existing checkpoints without specifying a training budget.

The dataset-specific architecture and optimizer settings in the YAML files come from the public implementation. These presets and example seeds provide a runnable baseline. Exact reproduction of the manuscript's aggregate results requires the original run configurations and seeds.

## Implementation

- `models/model.py` and `models/reconstructor.py` implement dual-domain reconstruction, patching, and reconstruction fusion.
- `models/prototype_retrieval.py` implements batched variable-wise top-k retrieval and the two-term prototype loss.
- `models/n_gram.py` and `solver.py` implement temporal transitions, cross-variable dependencies, calibration, and evaluation.

Please use GitHub Issues for implementation questions.
